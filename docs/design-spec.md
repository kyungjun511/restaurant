# 디자인 설계서 — 점심 미리주문

> 연결 문서: service-plan.md (기능 F-ID, 화면 S-ID, 흐름 FL-ID 동일)
> 기준: React Native 기본 컴포넌트 + Expo 기본 라이브러리로 만들 수 있는 수준
> 시스템 기본 폰트 사용 (iOS: San Francisco / Android: Roboto·Noto Sans KR)

---

## 1. 디자인 컨셉

### 1.1 분위기 키워드 [제안]
**빠른 · 따뜻한 · 깔끔한 · 믿을 수 있는 · 쉬운**

### 1.2 톤앤매너 [제안]
- **직원 화면**: 음식 앱다운 따뜻한 주황색 포인트. 사진 중심, 여백 넉넉하게.
- **사장님 화면**: 주방에서 한 손으로 빠르게 쓰도록 글자와 버튼을 더 크게. 장식 없이 "도착 시간·인원·메뉴"만 크게.
- **관리자 화면**: 목록과 입력 위주의 단정한 화면.
- **문구**: 존댓말, 짧은 해요체. 예) "주문을 보냈어요", "결제는 매장에서 해요"

## 3. 공통 컴포넌트

### 3.1 버튼 (Button)

| 종류 | 모양 | 쓰는 곳 |
|---|---|---|
| 주요 버튼 | 주요색 배경 + 흰 글자, 높이 52 (사장님 56), 가로 꽉 채움 | 로그인, 주문 요청하기, 수락, 상태 변경 |
| 보조 버튼 | 흰 배경 + 테두리 + 보조색 글자 | 홈으로, 거절 |
| 위험 버튼 | 흰 배경 + 오류색 테두리·글자 | 삭제, 노쇼 처리, 주문 취소 |
| 텍스트 버튼 | 배경 없이 글자만 (주요색) | 음식점·관리자 로그인 전환 |

| 상태 | 표시 |
|---|---|
| 기본 | 위 모양 그대로 |
| 눌림 | 주요 버튼은 Primary Pressed, 보조 버튼은 배경 `#F3F4F6` |
| 비활성 | 배경 Disabled, 글자 흰색, 누를 수 없음 |
| 로딩 | 글자 대신 작은 로딩 표시, 누를 수 없음 |

### 3.2 입력창 (Input)
- 높이 52, 흰 배경, 테두리, 모서리 10, 위에 라벨(14)
| 상태 | 표시 |
|---|---|
| 기본 | 테두리 Border |
| 입력 중(포커스) | 테두리 Primary 2px |
| 비활성 | 배경 `#F3F4F6`, 글자 Text Sub |
| 오류 | 테두리 Error + 아래 빨간 안내 문구(12) |

### 3.3 선택창 (Select)
- 입력창 모양 + 오른쪽 `chevron-down` 아이콘. 누르면 바텀시트 목록이 열림
- 상태: 입력창과 동일 (선택 전에는 회색 안내 문구)

### 3.4 카드 (Card)
| 종류 | 내용 |
|---|---|
| 음식점 카드 | 대표 사진(16:9) + 이름 + 위치·영업시간 + 영업 배지 |
| 주문 카드 (직원) | 상태 배지 + 음식점명 + 도착 시간·인원 + 메뉴 요약 + 금액 |
| 주문 카드 (사장님) | 도착 시간(큰 글자) + 인원 + 메뉴 요약 + 회사·이름 + 상태 배지 |

| 상태 | 표시 |
|---|---|
| 기본 | 흰 배경 + 옅은 그림자 |
| 눌림 | 배경 `#F9FAFB` |
| 비활성 | 전체 투명도 50% (예: 오늘 주문 마감 음식점) |
| 강조 | 주요색 테두리 2px + Primary Light 배경 (사장님 신규 주문) |

### 3.5 리스트 항목 (List Item)
- 메뉴 항목: 왼쪽 사진(64×64) + 메뉴명·설명·가격 + 오른쪽 "담기" 또는 수량 조절기
- 설정·정보 항목: 왼쪽 라벨 + 오른쪽 값 또는 스위치, 높이 56
| 상태 | 표시 |
|---|---|
| 기본 | 흰 배경, 아래 구분선 |
| 눌림 | 배경 `#F9FAFB` |
| 비활성 | 글자 Disabled + "품절" 배지 |

### 3.6 수량 조절기 (Stepper)
- `−  2  +` 형태, 버튼 각 40×40
- 상태: 최소값(1)이면 `−` 비활성, 최대값이면 `+` 비활성

### 3.7 칩 (Chip)
- 도착 시간·필터 선택용, 높이 40, 끝까지 둥글게
| 상태 | 표시 |
|---|---|
| 기본 | 흰 배경 + 테두리 |
| 선택됨 | Primary Light 배경 + 주요색 테두리·글자 |
| 비활성 | 글자 Disabled (예: 이미 지난 시간) |

### 3.8 상태 배지 (Badge)
- 높이 24, 글자 12 SemiBold, 2.1의 상태 배지 색 사용
- 영업 배지: "영업 중"(성공색), "오늘 주문 마감"(회색)

### 3.9 스위치 (Switch)
- React Native 기본 Switch, 켜짐 색 Primary
- 상태: 켜짐 / 꺼짐 / 비활성(회색, 누를 수 없음)

### 3.10 탭바 (하단 탭)
- 높이 56 + 하단 안전 영역, 아이콘 24 + 글자 12
- 상태: 선택(주요색, 채운 아이콘) / 기본(Text Sub, 선 아이콘)

### 3.11 상단 탭 (Segmented Tab)
- 화면 안에서 목록을 나누는 탭 (예: 진행 중 / 지난 주문, 신규 / 진행 중 / 완료)
- 선택: 주요색 글자 + 아래 2px 선 / 기본: Text Sub
- 개수 배지 표시 가능: "신규 3"

### 3.12 헤더 (Header)
- 높이 56, 흰 배경, 가운데 또는 왼쪽 제목(18 SemiBold)
- 왼쪽: 뒤로가기(하위 화면만), 오른쪽: 텍스트 버튼(선택)

### 3.13 하단 고정 바 (Bottom Bar)
- 화면 아래에 붙는 영역, 흰 배경 + 위쪽 구분선, 안쪽 여백 16 + 하단 안전 영역
- 장바구니 바(S-04), 주문 버튼(S-05), 상태 변경 버튼(S-10)에 사용

### 3.14 모달 (확인창)
- 가운데 흰 상자, 제목 + 설명 + 버튼 2개(취소 / 확인)
- 쓰는 곳: 주문 취소, 노쇼 처리, 메뉴 삭제, 장바구니 비우기

### 3.15 바텀시트 (Bottom Sheet)
- 아래에서 올라오는 흰 영역, 위쪽 모서리 16, 배경 어둡게(투명도 40%)
- 쓰는 곳: 회사 선택, 거절 사유 선택, 직원·회사·음식점 추가 입력
- [선택] 손가락으로 끌어내려 닫기 제스처는 선택 사항. 기본은 "닫기" 버튼과 배경 탭으로 닫기

### 3.16 빈 화면 (Empty State)
- 가운데 아이콘(48, Text Sub) + 안내 문구(16) + 보조 문구(14) + 버튼(선택)

### 3.17 로딩 (Loading)
- 목록 처음 불러올 때: 화면 가운데 기본 로딩 표시(ActivityIndicator, 주요색)
- 당겨서 새로고침: 목록 위 기본 새로고침 표시
- 버튼 처리 중: 버튼 안 로딩 (3.1)

### 3.18 오류 표시 (Error)
- 화면 전체 오류: `alert-circle-outline` + "불러오지 못했어요" + "다시 시도" 버튼
- 입력 오류: 입력창 아래 빨간 문구 (3.2)
- 처리 실패: 화면 위쪽 빨간 안내 띠(3초 후 사라짐)

### 3.19 안내 띠 (Banner)
- 화면 위쪽 가로 띠, 높이 44
- 정보(Primary Light 배경), 성공(초록 연한 배경), 오류(빨강 연한 배경)
- 쓰는 곳: 주문 마감 안내, 저장 완료, 처리 실패

## 4. 내비게이션 구조

로그인한 사용자 유형에 따라 서로 다른 탭 묶음으로 이동합니다.

```
S-01 로그인
 ├─ (첫 로그인) S-02 비밀번호 변경
 │
 ├─ [직원] 하단 탭
 │   ├─ 홈 탭
 │   │   └─ S-03 홈 (음식점 목록)
 │   │       └─ S-04 음식점 상세 (메뉴판)
 │   │           └─ S-05 장바구니 / 주문하기
 │   │               └─ S-06 주문 완료 ──→ S-07 / S-03
 │   ├─ 내 주문 탭
 │   │   └─ S-07 내 주문 (진행 중 | 지난 주문)
 │   └─ 마이 탭
 │       └─ S-08 마이페이지
 │           └─ S-02 비밀번호 변경
 │
 ├─ [사장님] 하단 탭
 │   ├─ 주문 탭
 │   │   └─ S-09 오늘의 주문 (신규 | 진행 중 | 완료)
 │   │       └─ S-10 주문 상세
 │   ├─ 요약 탭
 │   │   └─ S-11 시간대별 요약
 │   ├─ 메뉴 탭
 │   │   └─ S-12 메뉴 관리
 │   │       └─ S-13 메뉴 등록·수정
 │   └─ 설정 탭
 │       └─ S-14 가게 설정
 │
 ├─ [회사 관리자] 상단 탭
 │   ├─ S-15 직원 명단
 │   └─ S-16 가입 승인 (2차)
 │
 └─ [총괄 관리자] 하단 탭
     ├─ S-17 회사 관리
     ├─ S-18 음식점 관리
     └─ S-19 주문 현황
```

- 하위 화면(S-04, S-05, S-06, S-10, S-13)에서는 하단 탭을 숨기지 않고 유지합니다. [가정]
- S-06 주문 완료에서는 뒤로가기를 막고, "내 주문 보기" / "홈으로" 버튼으로만 이동합니다. (중복 주문 방지)

## 5. 화면별 상세 설계

와이어프레임 기호: `[ ]` 버튼·입력창, `( )` 이미지·아이콘, `< >` 배지, `---` 구분선

---

### S-01 로그인
- **목적**: 사용자 유형별로 로그인하고 다음 화면으로 보냄
- **관련 기능**: F-01, F-13

**레이아웃**
1. 상단: 로고 + 서비스명
2. 로그인 방식 전환: 직원 / 음식점·관리자
3. 입력 영역
4. 로그인 버튼

```
            (로고)
         점심 미리주문
  같은 건물 맛집, 미리 주문하고 바로 식사

  [ 직원 ]  [ 음식점·관리자 ]      ← 상단 탭

  회사
  [ 회사를 선택해 주세요       ▼ ]
  사번
  [ 사번을 입력해 주세요         ]
  비밀번호
  [ ●●●●●●                    ]

  [          로그인            ]
```
(음식점·관리자 탭에서는 "회사·사번" 대신 "아이디" 입력창 1개)

**구성 요소**

| 요소 | 종류 | 표시 내용 | 공통 컴포넌트 |
|---|---|---|---|
| 로고 | 이미지 | 앱 로고 | — |
| 서비스명·소개 | 텍스트 | 점심 미리주문 / 소개 문구 | — |

### S-04 음식점 상세 — 메뉴판
- **목적**: 메뉴를 보고 장바구니에 담기
- **관련 기능**: F-04, F-05, F-20

**레이아웃**

  (사진) 제육볶음               <품절>
         10,000원
  ---
  ┌────────────────────────────┐
   (카트) 2개 · 16,000원  [주문하기]

| 요소 | 종류 | 표시 내용 | 공통 컴포넌트 |

| 품절 표시 | 배지 | 품절 | 배지 |

**상태별 화면**

### S-05 장바구니 / 주문하기
- **목적**: 주문 내용 확정 후 주문 요청
- **관련 기능**: F-05, F-06, F-07, F-08

**레이아웃**
1. 헤더: 뒤로가기 + "주문하기"
2. 음식점명 + 담은 메뉴 (수량 조절)
3. 도착 시간 선택 (칩, 가로 스크롤)
4. 식사 인원 (수량 조절기)
5. 요청사항 입력
6. 결제 안내 + 합계
7. 하단 고정 "주문 요청하기" 버튼

```
  [<]  주문하기
  ---
  건물 앞 백반집
  김치찌개   9,000원        [ − 2 + ]
  된장찌개   8,000원        [ − 1 + ]
  ---
  도착 시간
  [11:50] [12:00] [12:10] [12:20] →
  ---
  식사 인원                  [ − 2 + ]
  ---
  요청사항 (선택)
  [ 예: 덜 맵게 해주세요          ]
  ---
  결제는 매장에서 현장 결제해요
  합계                      26,000원
  ---
  [       주문 요청하기          ]
```

**구성 요소**

| 요소 | 종류 | 표시 내용 | 공통 컴포넌트 |
|---|---|---|---|
| 헤더 | 헤더 | 주문하기, 뒤로가기 | 헤더 |
| 담은 메뉴 | 리스트 항목 | 메뉴명, 가격, 수량 | 리스트 항목, 수량 조절기 |
| 도착 시간 | 칩 묶음 | 11:30~13:00, 10분 단위 [가정] | 칩 |
| 식사 인원 | 조절기 | 1~10명 [가정] | 수량 조절기 |
| 요청사항 | 입력창 | 최대 50자 [가정] | 입력창 |
| 결제 안내 | 텍스트 | 현장 결제 안내 | — |
| 합계 | 텍스트 | 총 금액 | — |
| 주문 버튼 | 버튼 | 주문 요청하기 | 주요 버튼, 하단 고정 바 |

**상태별 화면**
- 기본: 도착 시간 미선택이면 버튼 비활성, 인원 기본값 1
- 지난 시간: 현재 시각보다 이른 칩은 비활성
- 로딩: 버튼 로딩, 화면 입력 막음
- 비어 있음: 메뉴를 모두 빼면 (`cart-outline`) "장바구니가 비었어요" + [메뉴 보러 가기]
- 오류: 위쪽 빨간 띠 "주문을 보내지 못했어요. 다시 시도해 주세요"
- 마감 후: 버튼 비활성 + 안내 "오늘 주문이 마감됐어요"
- 성공: S-06으로 이동, 장바구니 비움

**동작**
- 칩 탭 → 하나만 선택됨
- 요청사항 입력 시 키보드가 입력창을 가리지 않도록 화면이 위로 밀림
- "주문 요청하기" → 주문 요청 → S-06

**문구**
- 버튼: "주문 요청하기", "메뉴 보러 가기"
- 섹션: "도착 시간", "식사 인원", "요청사항 (선택)"

### S-10 주문 상세 (사장님)
- **목적**: 주문 내용을 확인하고 수락·거절·상태 변경
- **관련 기능**: F-07, F-16, F-17

  ---

  된장찌개                     × 1
  ---

  덜 맵게 해주세요
  ---
  합계 26,000원 · 현장 결제
  ---
  [   거절   ]  [      수락      ]
```

**상태별 하단 버튼**

| 현재 상태 | 버튼 |
|---|---|
| 주문 요청 | [거절] (보조) + [수락] (주요) |
| 주문 수락 | [준비 시작] (주요) |
| 준비 중 | [준비 완료] (주요) |
| 준비 완료 | [제공 완료] (주요) + "노쇼 처리" (위험, 작게) |
| 제공 완료 / 거절 / 취소 / 노쇼 | 버튼 없음, 처리 결과만 표시 |

**거절 사유 바텀시트**
```
  거절 사유를 선택해 주세요
  ( ) 품절
  ( ) 만석
  ( ) 시간 불가
  ( ) 기타
  [        거절하기          ]
```

**구성 요소**

| 요소 | 종류 | 표시 내용 | 공통 컴포넌트 |
|---|---|---|---|
| 헤더 | 헤더 | 주문 번호, 상태 배지 | 헤더, 배지 |
| 도착 시간·인원 | 텍스트 | 28 Bold / 18 | — |
| 주문자 | 리스트 항목 | 회사·이름 | 리스트 항목 |
| 메뉴 | 리스트 항목 | 메뉴명 × 수량 | 리스트 항목 |
| 요청사항 | 텍스트 | 요청사항 (없으면 숨김) | — |
| 합계 | 텍스트 | 금액 · 현장 결제 | — |
| 상태 버튼 | 버튼 | 상태별 버튼 | 주요·보조·위험 버튼, 하단 고정 바 |
| 거절 사유 | 바텀시트 | 4가지 사유 | 바텀시트 |

- 로딩: 누른 버튼 로딩
- 오류: 위쪽 빨간 띠 "처리하지 못했어요. 다시 시도해 주세요"
- 이미 취소된 주문: 버튼 대신 안내 "직원이 취소한 주문이에요"
- 성공: 안내 띠 "수락했어요" 등, 상태 배지와 버튼이 다음 단계로 바뀜

**동작**

**문구**

  설명 (선택)
  [ 예: 돼지고기 듬뿍            ]

  [          저장하기          ]
  [          메뉴 삭제          ]   ← 수정 시만
```

**구성 요소**

| 요소 | 종류 | 표시 내용 | 공통 컴포넌트 |
|---|---|---|---|
| 헤더 | 헤더 | 메뉴 등록 / 메뉴 수정 | 헤더 |
| 사진 | 이미지 | 선택한 사진 미리보기 | — |
| 사진 버튼 | 버튼 | 사진 선택 / 사진 찍기 | 보조 버튼 |
| 메뉴명 | 입력창 | 최대 20자 [가정] | 입력창 |
| 가격 | 입력창 | 숫자 키보드 | 입력창 |
| 설명 | 입력창 | 최대 40자 [가정] | 입력창 |
| 저장 | 버튼 | 저장하기 | 주요 버튼 |
| 삭제 | 버튼 | 메뉴 삭제 (수정 시) | 위험 버튼 |

**상태별 화면**
- 기본: 메뉴명·가격이 있어야 저장 활성
- 로딩: 저장 버튼 로딩
- 오류: 가격 칸 아래 "숫자만 입력해 주세요", 저장 실패 시 빨간 띠
- 성공: 안내 띠 "저장했어요" → S-12

**동작**
- 사진 선택 → 폰 앨범 열림 / 사진 찍기 → 카메라 열림 (처음엔 권한 요청)
- 가격 입력 시 숫자 키보드
- 메뉴 삭제 → 모달 확인 → S-12

**문구**
- 버튼: "사진 선택", "사진 찍기", "저장하기", "메뉴 삭제"
- 입력 안내: "예: 김치찌개", "예: 9000", "예: 돼지고기 듬뿍"
- 모달: 제목 "메뉴를 삭제할까요?" / 설명 "삭제하면 직원 메뉴판에서 사라져요." / 버튼 "취소", "삭제"
- 오류: "메뉴명을 입력해 주세요", "숫자만 입력해 주세요", "저장하지 못했어요. 다시 시도해 주세요"
- 권한 안내: "사진을 올리려면 사진 접근 권한이 필요해요"

## 6. 모바일 고려사항

| 항목 | 규칙 |
|---|---|
| 터치 영역 | 누를 수 있는 모든 요소는 최소 44×44. 사장님 화면 버튼은 높이 56 |
| 키보드 | 입력창이 있는 화면(S-01, S-02, S-05, S-13, S-14, 바텀시트)은 키보드가 올라오면 화면을 위로 밀어 입력창이 가려지지 않게. 화면 빈 곳을 탭하면 키보드 닫힘 |
| 숫자 입력 | 사번·가격·시간 입력은 숫자 키보드 |
| 안전 영역 | 노치(화면 위 카메라 부분)와 하단 홈 바 영역에 내용이 겹치지 않게. 하단 고정 바·탭바는 하단 안전 영역만큼 아래 여백 추가 |
| 작은 화면 | 가로 360 기준으로 설계. 도착 시간 칩은 가로 스크롤, 긴 메뉴명은 2줄까지 표시 후 말줄임(…) |
| 글자 대비 | 본문 글자는 배경 대비 4.5:1 이상. 주요색 버튼 위 흰 글자 대비 충족 (2.1 참고) |
| 큰 글씨 설정 | 폰 글자 크기를 키워도 버튼 글자가 잘리지 않게 버튼 높이는 고정하지 않고 최소값만 지정 |
| 색만으로 구분 금지 | 주문 상태는 색과 함께 반드시 글자(배지)로 표시 |
| 실수 방지 | 되돌릴 수 없는 동작(거절, 노쇼, 취소, 삭제, 비활성화)은 모두 확인 모달 또는 바텀시트를 거침 |
| 한 손 조작 | 사장님 화면의 주요 버튼은 화면 아래쪽(하단 고정 바)에 배치 |

## 8. 개발 설계서로 넘길 사항

| 항목 | 정해야 할 내용 |
|---|---|
| 데이터 저장 방식 | 회사·사용자·음식점·메뉴·주문 정보를 어디에, 어떻게 저장할지 |
| 기기 간 정보 공유 | 직원 폰의 주문이 사장님 폰에 보이게 하는 방법 |
| 상태 반영 방식 | 주문 상태를 자동으로 바로 반영할지, 새로고침으로 가져올지 (F-10, F-14) |
| 로그인 처리 | 회사 + 사번 / 아이디 로그인 확인, 로그인 유지, 비밀번호 보관, 사용자 유형별 화면 분기 |
| 화면 간 정보 전달 | 장바구니 내용(S-04 → S-05), 주문 결과(S-05 → S-06), 주문 번호(S-09 → S-10) |
| 장바구니 보관 | 앱을 껐다 켜도 장바구니를 유지할지 |
| 시간 처리 | 현재 시각 기준 지난 도착 시간 비활성, 주문 마감 판단 |
| 푸시 알림 | 2차에서 실제 알림을 넣을 때 필요한 별도 빌드와 알림 발송 방법 (F-11, F-14) |
| 사진 처리 | 메뉴 사진 촬영·선택 권한, 사진 크기 줄이기, 저장 위치 (F-19) |
| 가짜 데이터 | Must 단계에서 쓸 회사·음식점·메뉴·계정 샘플 데이터 형식 |
| 사용 라이브러리 | 화면 이동(탭·스택), 사진 선택, 안전 영역 처리에 쓸 Expo 라이브러리 |
| 폴더·컴포넌트 구조 | 3장의 공통 컴포넌트를 코드로 어떻게 나눌지 |
